# Arbetsrutin för Elevantly

Denna fil kompletterar CLAUDE.md. Läs alltid CLAUDE.md först — den är
grundlagen och vinner vid konflikt.

## Innan du börjar en uppgift
1. Läs CLAUDE.md och den kod uppgiften rör.
2. Formulera vilken **användarfråga** uppgiften tjänar. Saknas en — fråga.
3. Kör sju-dagars-testet (CLAUDE.md 5.1). Klarar den inte testet: säg det.

## Medan du arbetar
- Gör minsta möjliga förändring som löser uppgiften.
- Vid ett beslut med avvägningar: stanna, presentera alternativ, vänta.
- Håll strukturerad data strukturerad; låt inte fritext driva logiken.

## Innan du levererar (checklista, samma som Definition of Done)
- [ ] Tjänar en namngiven användarfråga
- [ ] Ingen manual krävs för att förstå den
- [ ] Data är korrekt strukturerad och typad
- [ ] Bryter inte mot "Detta bygger vi aldrig" (CLAUDE.md 10)
- [ ] Privacy/GDPR genomtänkt
- [ ] Testad, och du rapporterar vad du testat
- [ ] Levererad som PR med beskrivning av användarfråga + ändring + test
